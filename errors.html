03

依情境進行初步排查

先保留錯誤訊息與重現步驟，再選擇符合情境的操作。不需要為每個問題都重新安裝套件。

重新啟動開發伺服器10 秒

若設定或套件變更尚未生效，可在開發伺服器的終端機按 Ctrl＋C 停止，再依專案指令啟動。部分工具可自動載入變更，是否需要重啟應以工具行為為準。

Ctrl + C npm run dev

檢查較早出現的相關錯誤30 秒

一次操作可能連續產生多個錯誤。在瀏覽器開啟開發者工具的 Console，依時間順序檢查與這次操作相關的訊息。較早的錯誤可能引發後續問題，但仍需確認因果關係。

依鎖檔重新安裝套件2 到 5 分鐘

若安裝不完整，且專案有與 package.json 一致的 npm 鎖檔，可使用 npm ci。它會移除現有 node_modules 並依鎖檔重新安裝；其中未保存的本機修改會遺失。若是版本相容性問題，仍需先處理衝突，避免直接刪除鎖檔。

npm ci
04

整理求助時需要的資訊

提供可重現的情境與相關程式，能讓協助者更容易定位問題。先列出關鍵訊息，再按需要補充完整堆疊。分享前移除金鑰、密碼與個人資料。

我遇到這個錯誤： <貼上錯誤類型與完整訊息> 錯誤涉及的檔案： <貼上指向專案原始碼的堆疊紀錄> 錯誤發生前的操作： <例如：我在 ArticleCard 裡加了 article.title 這一行> 環境：<框架名稱與版本、執行環境版本、作業系統> 預期結果與實際結果： <說明預期行為，以及如何重現問題>
建議提供
· 錯誤類型與完整訊息
· 指向專案原始碼的堆疊紀錄
· 近期修改與重現問題的操作步驟
· 框架、執行環境與作業系統版本
分享前檢查
· 完整堆疊可保留備查，依排查需要補充
· 程式片段需包含足以重現問題的上下文
· 錯誤訊息優先以文字提供，方便搜尋與引用
· 移除 .env 中的金鑰與連線憑證，以遮蔽值代替

延伸閱讀：npm ci、React 更新循環、MDN CORS。
