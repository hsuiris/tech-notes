01

一段錯誤訊息，只有兩行要看

下面這段錯誤訊息被分成三塊，點任何一塊，右邊會說明那塊在講什麼、要不要看。

← 點左邊任何一塊，這裡會說明它在講什麼。

看第一行知道發生什麼事，看有你檔名的那一行知道在哪裡發生。
其他行有 node_modules 這個字的，一律跳過。
02

16 個最常見的錯誤

把你看到的關鍵字貼進搜尋框就會篩出來。每一則的重點放在它在說什麼，以及你下一步先動哪裡。

沒找到。試試更短的關鍵字，例如只貼一個英文單字。

03

問人之前，先自己試這三招

順序照排，不要跳。

關掉重開10 秒

在跑程式的那個終端機視窗按 Ctrl ＋ C 停掉，再重跑一次。改了設定檔、裝了新套件之後，一定要這樣做。舊的還在記憶體裡跑，你看到的是過期的畫面。

Ctrl + C npm run dev

看更早的那個紅字30 秒

你看到的紅字，常常不是第一個錯誤，只是最後倒下的那個。在瀏覽器按 F12（Mac 是 Cmd＋Option＋I）打開 Console，往上捲到最上面，第一個紅字才是元兇。

砍掉重裝2 到 5 分鐘

只在「裝套件出事」或「版本打架」時才用。它會刪掉所有下載來的套件重裝一次，是最後手段但很有效。只刪 node_modules，不會動到你寫的東西。

rm -rf node_modules package-lock.json npm install
04

貼給 AI 的正確方式

整段貼 40 行反而會讓 AI 抓錯重點。照下面這樣貼，答對率比較高。

我遇到這個錯誤： <貼第 1 行，就是有 Error 那行> 出事的檔案： <貼有我自己檔名的那 1～2 行> 我剛剛做了什麼： <例如：我在 ArticleCard 裡加了 article.title 這一行> 環境：Next.js 15 · macOS
要貼的
· 第一行（錯誤類型 ＋ 訊息）
· 有你自己檔名的那 1～2 行
· 你剛剛改了什麼、做了什麼動作
· 用什麼框架、什麼作業系統
不要貼的
· 含 node_modules 的那幾十行
· 整個檔案的程式碼（先貼出事那 10 行就好）
· 螢幕截圖裡看不清楚的紅字（用複製的）
· 你的 .env 內容，裡面是密碼，貼出去等於外洩

整頁只有一個重點：錯誤訊息只要你找出那兩行，不用全部看懂。
找到之後，剩下的交給 Google 或 AI 都行，但你得先知道要問什麼。
