02

六個要先做的取捨

即時算，還是先算好？

即時算使用者一來才算，資料最新
先算好每天算一次存起來，直接查

業界的統計是，真正需要即時算的大概只佔一到兩成。而且即時算每一次預測的成本，大約是先算好的 25 到 50 倍。
所以先問自己：答案隔一天才更新，使用者會不會有感覺？多數情況是不會，那就先算好。

大模型，還是小模型？

大模型答得好，但慢又貴
小模型快又便宜，但差一點

常見的做法是兩個都用：先讓小模型把明顯的處理掉，只有它拿不定主意的才丟給大模型。
要決定怎麼分，先去量「有多少比例是簡單的」。如果九成都很簡單，那九成的量根本不需要大模型。

自己訓練，還是打別人的 API？

自己訓練資料留在自己手上，長期較便宜
打 API今天就能用，但每次都要付錢

先打 API 做出來，有量了再考慮自己訓練。自己訓練的成本不只是機器，還要養一整組人維護。
要換的時候算一下：一個月的 API 帳單，跟一個工程師的月薪，哪個多？差很遠就繼續打 API，不用糾結。

準一點，還是快一點？

準多算幾層、多查幾次
快砍步驟，先給答案

這題要先問清楚「慢多久使用者會走」。搜尋結果慢 1 秒就有人離開，可是每月報表慢 10 分鐘沒人在意。
做法是先定死一個延遲上限，然後在這個上限裡面盡量做準。順序不能反過來。

資料要多新？

越新越好剛剛的行為馬上反映
舊一點沒差每天更新一次

資料要越新，整套系統就越貴越複雜。新鮮度是把成本推高最兇的東西之一。
所以先問：使用者剛剛做的事，多久之後看到效果才算合理？多數情境幾小時就夠了，真的不用追到秒。

錯了哪一種比較嚴重？

誤判為有問題好東西被擋下來
漏掉真的有問題壞東西溜過去

這兩種錯不可能同時降到最低，只能選一邊。審核內容寧可誤擋，推薦商品寧可漏掉。
不知道怎麼選的時候，問一個很實際的問題：哪一種錯誤上新聞比較慘？往那邊調就對了。

RAG 是怎麼運作的

RAG（Retrieval-Augmented Generation，檢索增強生成）的意思是先去查資料，再叫 AI 根據查到的東西回答。點任何一站看它在做什麼。

← 點左邊任何一站，這裡會說明它在做什麼、最常出什麼問題。

RAG 答錯的時候，八成不是 AI 笨，是它根本沒拿到正確的段落。
所以要分開檢查：查到的段落對不對是一件事，拿到段落之後答得好不好是另一件事。這兩件混在一起看，你永遠找不到問題出在哪。
