Claude 技能

建立 Claude 技能

01

先認識擴充功能的用途

當同一套工作方法需要反覆說明時，可以把它整理成技能。若需求涉及獨立子任務、自動檢查或外部服務，則可能需要其他擴充方式。點選項目查看差異。

選擇一個項目，查看用途、位置與注意事項。

Plugin（外掛）可將技能、子代理與相關設定整理成可安裝的套件。個別元件不必全部具備，只有一個技能的外掛也能成立。

個人設定與專案設定

個人偏好可放在主目錄的 ~/.claude/。需要隨專案共享的指示，則可放在專案內的 .claude/ 並納入版本控制。以下為常見位置示意。

~/.claude/ ├── skills/my-first-skill/SKILL.md ├── commands/review-code.md ├── agents/reviewer.md └── settings.json 專案資料夾/ ├── .claude/skills/team-review/SKILL.md └── .mcp.json

子代理的角色與工具

子代理定義也使用 Markdown 與 YAML 前置資料。以下是只列出讀取與搜尋工具的示例；實際權限仍須確認執行環境。

--- name: reviewer description: 閱讀指定檔案，回報可驗證的問題與對應位置。 tools: Read, Grep, Glob --- 依提供的需求檢查內容。回報問題、檔案位置與判斷依據。 若缺少資訊，明確指出，不推測未讀取的內容。
02

技能內容如何組織

先把工作規則寫清楚，再依需求加入資料或程式。不同結構可搭配使用，沒有必須逐級擴充的順序。

工作指示

以 SKILL.md 為主

適合寫作規則、審查清單與操作步驟。純文字仍需維護，尤其是工具行為或團隊規範改變時。

參考資料

加入 references/

把較長的對照表、規格與範例另外保存，在主文件說明何時查閱。避免同一規則在多處重複維護。

可執行腳本

加入 scripts/

計算、轉檔與格式驗證可由程式處理。腳本需要環境條件、錯誤處理與測試，不能只依賴文字指示。

子任務協作

定義分工與交接

只有任務可獨立處理且有整合方式時，才考慮多代理。詳見多代理協作。

三個設計案例

以下保留原頁介紹的案例主題，著重可參考的組織方式。檔案數、行數與可用功能會隨版本變動，不作為固定規格。

將視覺要求寫成可檢查的指示

圖像技能可描述畫面用途、尺寸與需要保留的元素。例如，多個網頁區塊各需要一張圖片時，可明確規定輸出數量與檔名，並要求逐張確認。

這類技能的價值在於讓反覆出現的品質要求有一致依據。文字指示本身不會產生圖片，仍需配合可用的圖像工具。

可參考的做法：把抽象偏好改成可檢查條件。例如寫明「每張圖對應哪個區塊」，比只要求「更有設計感」容易驗收。

將流程與專業方法分開維護

財務分析工具包可將資料整理、同業比較與模型計算拆成不同技能，再由入口指令安排先後順序。引用外部資料時，需保留來源、時間與計算假設。

MCP 設定只提供資料連接方式，實際存取仍取決於帳號、訂閱與授權。不能只因設定中列有服務名稱，就認定資料已可取得。

可參考的做法：讓多個流程共用同一套方法，更新時也要檢查使用它的其他流程。

由程式準備可分析的媒體內容

影片處理流程可以包含擷取影格、取得字幕與語音轉文字，再交給模型整理。各步驟是否可用，取決於來源存取方式、工具與權限。

SKILL.md 應說明何時執行腳本、如何判讀結果，以及失敗時如何處理。環境檢查則可在合適的事件掛鉤中執行，並清楚回報缺少的條件。

可參考的做法：讓程式處理需要可重現的檔案操作，讓工作指示負責安排順序與檢查結果。
03

依需求決定需要哪些檔案

若只是整理固定的寫作或審查規則，一份 SKILL.md 就能開始。參考資料太長時，再拆出附件；需要穩定執行的計算或轉檔時，再加入腳本。

多人需要安裝與更新同一套內容時，可考慮外掛。只有專案團隊共用的技能，也可直接放在專案的 .claude/skills/，不一定需要建立外掛市集。

先用真實任務測試技能是否有幫助。確認用途後，再補上與實際需求相關的檔案。
04

建立並測試第一個技能

以下以個人使用的信件技能為例。初稿與一次測試可先安排約 15 至 30 分鐘；實際調整時間取決於需求。範例使用終端機與已安裝的 Claude Code。

建立技能目錄

確認此名稱尚未用於其他技能，再建立資料夾。

mkdir -p ~/.claude/skills/my-first-skill

寫入 SKILL.md

下列指令會寫入指定檔案；若檔案已存在，先保存原有內容。開頭的 YAML 區塊是 frontmatter，用於描述技能。

cat > ~/.claude/skills/my-first-skill/SKILL.md <<'EOF' --- name: my-first-skill description: 撰寫給客戶或合作對象的信件，包括交期說明、報價與服務回覆。內部筆記不使用此技能。 --- # 客戶信件 ## 工作方式 先確認收件對象、已知事實與希望對方採取的行動。 資訊不足時詢問必要內容，不自行補上日期、承諾或原因。 ## 寫作規則 以自然的臺灣繁體中文撰寫。 首段說明來信目的，後續段落交代依據與後續安排。 若需致歉，具體說明影響與已確認的補救方式。 ## 輸出 提供主旨與可供審閱的信件草稿。 僅撰寫草稿，不代替使用者寄出。 EOF

確認可以載入

在 Claude Code 輸入以下指令，確認技能可被找到。若未顯示，檢查目錄、檔名、設定與目前使用的版本。

/my-first-skill

測試自然語句與輸出品質

以實際情境測試，例如「請草擬通知客戶交期延後一週的信」。檢查是否選用技能、是否補問缺少的日期，以及是否自行編造原因。也測試不應觸發的內部筆記需求。

依結果調整描述與規則

description 應交代用途與適用情境。內容較多時，把長範例移至參考檔，並在 SKILL.md 清楚指向它。手動呼叫與自然語句觸發都需要測試。

技能採按需載入的設計，描述會影響選用，但不是觸發的唯一因素。設定、名稱衝突與版本行為都可能影響結果。更新方式請以官方技能文件為準。
05

將技能整理成可分享的外掛

外掛可統一管理版本與安裝方式。以下示範同一個 GitHub 儲存庫同時提供外掛與市集目錄的簡單結構。

my-plugin/ ├── .claude-plugin/ │ ├── plugin.json │ └── marketplace.json └── skills/ └── my-first-skill/ └── SKILL.md

技能目錄放在外掛根目錄的 skills/ 下。其他元件只在需要時新增，避免誤放進 .claude-plugin/。

外掛資訊

將以下 JSON 存成 .claude-plugin/plugin.json。發布前確認名稱、作者與授權符合實際情況。

{ "name": "my-plugin", "version": "0.1.0", "description": "提供客戶信件草稿的寫作指示", "author": { "name": "你的名字" }, "license": "MIT" }

市集目錄

將以下內容存成 .claude-plugin/marketplace.json。此範例的 source 指向儲存庫根目錄。

{ "name": "my-marketplace", "owner": { "name": "你的名字" }, "plugins": [ { "name": "my-plugin", "description": "客戶信件技能", "source": "./" } ] }

發布前檢查

先驗證 JSON 語法與外掛載入結果，並確認沒有機密資料。下列命令檢查格式；功能仍需在 Claude Code 中實際測試。

python3 -m json.tool .claude-plugin/plugin.json python3 -m json.tool .claude-plugin/marketplace.json

在 GitHub 建立空白儲存庫後，可依下列範例推送。請替換帳號與儲存庫名稱，提交前先查看暫存內容。

cd my-plugin git init git add .claude-plugin skills git diff --cached git commit -m "Add customer email skill" git branch -M main git remote add origin https://github.com/你的帳號/my-plugin.git git push -u origin main

安裝與驗證

在 Claude Code 加入市集，再安裝其中的外掛。對方需有權存取該儲存庫。

/plugin marketplace add 你的帳號/my-plugin /plugin install my-plugin@my-marketplace

安裝後可測試 /my-plugin:my-first-skill。外掛技能包含命名空間，與個人技能的指令名稱不同。

06

常見問題的檢查方向

技能未被選用

檢查 description 是否符合任務、技能是否可見，以及是否限制了自動呼叫。用明確指令與自然語句分別測試。

修改後仍出現舊行為

先確認正在使用的檔案位置與版本，排除同名技能或外掛快取。依目前版本文件重新載入，必要時以新工作階段測試。

外掛未載入

核對目錄層級、JSON 格式與安裝紀錄。技能通常位於外掛根目錄的 skills/，不在 .claude-plugin/ 內。

規則互相矛盾

刪除重複指示，釐清優先順序，並把較長的參考內容移至獨立檔案。用相同測試題比較修改前後的結果。

設定檔解析失敗

JSON 的逗號、引號與括號必須符合語法。使用 python3 -m json.tool 檢查後，還要確認欄位符合工具規格。

本頁聚焦 Claude Code 的技能與外掛。不同 AI 工具雖可能共用 Agent Skills 格式，載入位置、權限與擴充欄位仍可能不同。
